# 书童 · Memorant 产品原则（北星）

日期：2026-07-24（修订：场景复用 / 抗遗忘 / 经验迭代）  
类目：AI 工作助手（先开发、再扩展到任意知识工作）

## 一句话

在真实工作中主动接住可复用经验；当**类似场景**再次出现时（哪怕相隔数月、人已忘记），主动找出可参考或可直接应用的内容，减少重复劳动；并随新做法**自我升级**过时经验——**由助手主动完成，而不是等人吩咐。**

## 真正要解决的问题

不是「把开发笔记按项目归好类」，而是：

1. **场景复用** — 以后遇到类似情境，能参考或直接套用过去的结论与手法  
2. **辅助记忆** — 半年前做过、现在记忆模糊时，避免从零再摸一遍  
3. **经验迭代** — 早期经验跟不上新方式时，随新工作纠正、替代、强化（B→A、supersede），而不是永远躺着过期答案  

「对得上项目」只是匹配信号之一（多仓/多产品线时减少串台），**不是产品目的本身**。匹配的主轴是**相似场景**（问题形态、约束、决策类型、技术/业务语境等）。

## 优先级第零条：主动（Proactive First）

> **不是用户主动让你做，而是你来主动去做。**  
> 这条高于「功能多少」「目录漂不漂亮」，与「不添乱」并列约束实现方式。

### 主动指什么

| 环节 | 被动（反模式） | 主动（目标） |
|---|---|---|
| 采集 | 用户说「记一下」才写 journal | 关键节点自动落盘 |
| 提炼 | 用户说「请 Distill」才写 memory | 验证通过 / 提交 / 会话结束 / 文档定稿等节点默认 Distill |
| 召回 | 用户说「搜一下」才查 | 类似场景一出现（开干、提问、再踩坑、开同类文档）就注入可参考/可应用内容 |
| 升级 | 只等人打命令 | 独立成功 → 强化/promote；矛盾证据 → 纠正或替代，不静默留过期真相对 |

### 主动不等于骚扰

- 普通写入：Activity + 可选一行摘要  
- 冲突、高风险过期记忆、无法脱敏：才打断  
- 首期主动发生在**当前宿主会话**（不引入后台常驻模型）

### 验收（主动是否达标）

修完非平凡问题并验证通过后，**未口述「请提炼」**仍应写入 memory（或 `needs_attention`）。

### 验收（抗遗忘 / 场景复用是否达标）

相隔较久后再次出现相似问题表述时，系统应主动表面相关记忆（含当时的 claim、证据链、是否仍可信），使用户不必从零重复探索。

### 验收（经验迭代是否达标）

同一主题出现更优做法或矛盾证据时，旧记忆进入 `corrected` / `superseded` 或 B→A 强化，召回优先新结论，且 Activity 可追溯变更——而不是一直推半年前的过期步骤。

## 五条工作尺子（主动之下）

1. **接得住** — 关键信号进 Journal，不靠人记得记  
2. **炼得准** — 可引用证据；A/B 信任；场景与身份信号可对齐  
3. **场景可复用** — 相似情境下找出可参考或可应用之物（时间跨度以月计仍有效）  
4. **经验会进化** — 强化、纠正、替代；过期知识让路  
5. **不添乱** — 安静默认，冲突与过期风险才打断  

## 与「项目」的关系（纠偏）

| 错误理解 | 正确理解 |
|---|---|
| 产品 = 按项目归档的开发笔记 | 产品 = 跨时间的场景经验循环 |
| 召回成功 = project 字符串相等 | 召回成功 = 场景相似且结果仍可信；project/stack 只是提高精度的信号 |
| 记下来就结束 | 记下来只是开始；还要在再用时命中，并在过时时升级 |

Project Identity 规格仍然需要：多仓并列时减少错配；它服务「找得准」，不重新定义产品目的。

## 扩展方向

从开发 → 任意知识工作：换 Observer 与 kind，不换「主动 + 场景复用 + 抗遗忘 + 迭代」。  
PRD/ADR/会议决议：在定稿/采纳节点主动进经验循环，正文可外置，结论可复用。
